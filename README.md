# US Options Intraday Analysis Dashboard

A single-file (`index.html`) dashboard that scans US stocks/ETFs, scores intraday **CALL** and **PUT** setups, picks a strike, proposes entry / stop-loss / targets, and lets you **paper trade** the result.

> **For research and paper trading only.** It cannot place real orders, and no score, signal or target is a prediction or a guarantee of profit. Options can lose their entire value quickly. This is not financial advice.

---

## What's in this project

| File | Purpose |
|---|---|
| `index.html` | The whole dashboard (HTML + CSS + JavaScript). No build step, no npm. |
| `bridge.py` | Optional. A small local program that lets the dashboard read market data from **Moomoo OpenD**. |
| `README.md` | This file. |

## Quick start (demo, 2 minutes)

1. Double-click `index.html`, or deploy it (next section).
2. Go to **DATA SOURCES** → press **ENABLE DEMO MODE**.
3. Open **AUTO-PICKS**, review a card, press **Why / plan**, then **ADD TO PAPER**.

Demo mode is generated by a simulator and is labelled **🔵 SIMULATED** everywhere. It exists only to test the interface. Demo paper trades are stored and reported separately from live-data paper trades.

---

## Deploy on GitHub Pages

1. Create a GitHub repository (for example `options-dashboard`).
2. Upload `index.html` to the repository root.
3. **Settings → Pages → Build and deployment**: Source = *Deploy from a branch*, Branch = `main`, folder = `/ (root)`.
4. After a minute it is live at `https://USERNAME.github.io/REPOSITORY/`.

**Never commit API keys.** The app has no keys in its code; you type them into the page each time.

## Connecting real market data

The dashboard shows a data status at all times: 🟢 LIVE, 🟡 DELAYED, 🔵 SIMULATED, 🔴 OFFLINE. Status is worked out from the age of the latest price bar, not assumed. If every provider fails it shows OFFLINE and **does not invent any prices, options data or signals**.

### Option A — Moomoo (via OpenD + the bridge)

Moomoo does **not** provide a public web API that a browser can call. Market data comes from **OpenD**, a program that runs on your own computer. A web page can't talk to OpenD directly, so `bridge.py` sits between them.

```
Dashboard (browser)  ->  bridge.py (127.0.0.1:8888)  ->  OpenD (127.0.0.1:11111)  ->  Moomoo
```

**One-time setup (Windows)**

1. Install and log in to **Moomoo OpenD**. Leave it running.
2. Install Python 3, then in Command Prompt:
   ```
   pip install flask flask-cors pandas moomoo-api
   ```
3. Put `bridge.py` in a folder (for example Downloads).

**Each time you use it**

1. Start OpenD and log in.
2. In Command Prompt: `cd Downloads` then `py bridge.py`. You should see `Bridge on http://127.0.0.1:8888`.
3. In the dashboard → **DATA SOURCES** → Moomoo box:
   - Proxy endpoint: `http://127.0.0.1:8888`
   - API key / secret: leave **empty**. OpenD logs in with your Moomoo account; the bridge ignores them.
   - Press **CONNECT**, then **TEST CONNECTION** (expect "Connected").
4. Press **START LIVE DATA**.

> **Port note:** `11111` is OpenD's own port. Do not put it in the dashboard. Use the bridge port (`8888`). If 8888 gives a "forbidden socket" error, change `BRIDGE_PORT` in `bridge.py` (for example to `8899`) and use that in the dashboard.

> Chrome/Edge may ask to allow access to devices on your local network. Click **Allow**. Safari often blocks a website from reaching `localhost`, so use Chrome or Edge.

**What your Moomoo permissions must include:** US stock quotes and US options quotes (the OpenD window shows these under "Quotes Permissions"). Index data such as VIX needs separate index permission; without it VIX is skipped and the "high volatility" warning is unavailable.

**Bridge limits**
- Options up to **30 days** to expiry only (OpenD limits each chain request to a 30-day window).
- OpenD allows about 10 option-chain requests per 30 seconds, so the first scan is slow; the contract list is cached for 30 minutes.
- Option prices and Greeks come from snapshots. Check the first few results against the Moomoo app before trusting them.

### Option B — Polygon / Massive (direct from the browser)

1. Get an API key. Options snapshots (bid/ask, Greeks, open interest) need an **options plan**; real-time vs delayed depends on your plan.
2. **DATA SOURCES** → Polygon box → paste the key → **CONNECT** → **TEST CONNECTION** → **START LIVE DATA**.

Because the key is typed into a web page, anyone who can inspect the page could see it. Use a restricted or free key, never one with billing power you can't afford to expose.

### Fallback order

Under **Data source priority** pick the primary provider. If it fails, the dashboard shows the reason (authentication, timeout, rate limit, invalid response, unavailable endpoint) and tries the other connected provider. Demo mode is **never** used as an automatic fallback.

### Writing your own provider

Any backend can be connected through the "custom proxy" box if it serves two JSON endpoints (HTTPS, or `http://localhost`; CORS must be enabled):

- `GET /bars?symbol=SPY&tf=5` returns `[{t, o, h, l, c, v}]`, where `t` is a millisecond timestamp, oldest first, at least 60 bars.
- `GET /chain?symbol=NVDA` returns `[{exp:"2026-10-23", type:"C"|"P", strike, bid, ask, last, vol, oi, iv, delta, gamma, theta, vega}]`, with `iv` as a decimal (0.45 = 45%).

To add another direct API (Tradier, Twelve Data, Finnhub…), add an object with `bars()`, `chain()` and `ping()` next to `Polygon` in the `DATA PROVIDERS` section of `index.html`.

## Using the dashboard

| Tab | What it does |
|---|---|
| **OVERVIEW** | Counts of calls/puts/qualified setups, market regime, SPY/QQQ/IWM/DIA/VIX context. |
| **AUTO-PICKS** | Candidate CALL and PUT contracts as cards. 📈 Chart, **Why / plan**, **ADD TO PAPER**, **Reject**. |
| **OPTIONS CHAIN** | Calls \| Strike \| Puts for any scanned symbol and expiry. ATM and highest volume/OI highlighted. |
| **TECHNICAL ANALYSIS** | Indicator table per symbol; click a symbol for the multi-timeframe table. |
| **PAPER TRADING** | Open trades, live P&L, status alerts, performance statistics. |
| **TRADE JOURNAL** | Closed trades, export to CSV / JSON. |
| **WATCHLIST** | Add or remove tickers. |
| **SETTINGS** | Liquidity filters, delta range, DTE, R:R, ATR multiples, risk limits, chart provider. |
| **DATA SOURCES** | Provider configuration and START / STOP. |

### How a setup is scored (0–100, "Technical Confluence Score")

| Component | Max | Notes |
|---|---|---|
| Trend | 20 | EMA 9/20/50 alignment plus 15-minute trend |
| Momentum | 15 | RSI zone and MACD histogram |
| VWAP | 15 | Price vs session VWAP |
| Volume | 10 | Relative volume vs recent average |
| Price action | 10 | Breakout/breakdown, higher lows / lower highs |
| Market regime | 10 | Agreement with SPY/QQQ/IWM/DIA; reduced when VIX is elevated |
| Liquidity | 10 | Option volume, open interest, spread |
| IV quality | 5 | Implied vs realized volatility |
| Risk/reward | 5 | Meets your minimum R:R |

Labels: 50–64 weak, 65–74 **WATCH**, 75–84 **QUALIFIED**, 85+ **HIGH-CONFLUENCE**. Correlated indicators are grouped into single components so they are not double-counted. **This is not a probability of profit.**

### Strike, entry, stops and targets

- The strike is chosen from contracts that pass your delta range (default 0.35–0.65), DTE, volume, open interest and spread filters, ranked by liquidity and closeness to about 0.50 delta.
- Underlying levels: SL1/SL2 and T1/T2 are ATR(14, 5-minute) multiples from the entry (defaults 1.0 / 1.5 / 1.5 / 2.5).
- Option levels are projected from the underlying levels using delta and gamma.
- Setups below your minimum R:R (defaults 1.5 to T1 and 2.0 to T2), with excessive IV, wide spreads, low liquidity, missing Greeks, stale data or a closed market are rejected. The app will show **NO QUALIFIED SETUPS** instead of forcing a trade.

### Paper trading rules

- **P&L = (current option price − entry price) × 100 × quantity**, for calls and puts alike (you are long the option).
- **ADD TO PAPER** is blocked if the underlying, expiry, strike, call/put, option price or data timestamp is missing, or if your risk limits would be exceeded. Quantity is sized from your max risk per trade and max capital.
- **CLOSE** locks the exit price and realised P&L and writes the trade to the journal. **DELETE** removes it and it never counts in statistics.
- Rows highlight when price crosses a target or stop. Auto-close is **off** unless you enable it in Settings.
- Trades are saved in your browser's local storage. **Clearing site data erases them**, so export the journal regularly.

### Market hours

Everything uses US Eastern Time (daylight saving handled by the browser's time-zone database). Normal intraday signals are suspended when the market is closed. The header shows the session (pre-market, open, lunch, power hour, after-hours, closed) and the next open.

### Chart links

- **TradingView** opens the underlying's chart. TradingView does not accept a direct option-contract link here, so the app says: *"Direct option chart unavailable — opening underlying chart."*
- **Yahoo Finance** (Settings → Chart provider) opens the page for the exact option contract (OCC symbol, for example `NVDA261023C00180000`).

## Security

- No API keys are stored in the code. Keys typed into the page live **in memory only** and disappear on reload.
- A browser-only site cannot keep a private API secret safe. If a provider needs a secret, keep it on your own backend/proxy and let the dashboard talk to that.
- `bridge.py` only reads market data. It has no trading functions, and the dashboard has no live order buttons.

---

## Known limitations

- **Not tested against live providers by the author.** Demo mode and the calculations were tested; connections to Moomoo and Polygon were not. Verify results against your broker before relying on them.
- Indicators implemented: EMA 9/20/50, RSI, MACD, VWAP, ATR, relative volume, realized volatility. Not implemented: EMA 200, ADX, Supertrend, Stochastic RSI, OBV, Bollinger Bands.
- Timeframes: 5m / 15m / 30m / 1h, built from 5-minute bars. No 1m, 3m or daily.
- Not implemented: backtest/replay mode, news and earnings/event-risk detection (the app states earnings risk is not checked), IV rank/percentile, US market holiday calendar.
- Providers included: Moomoo (via bridge), Polygon, custom proxy, demo. Others must be added.
- Data is only as good as your subscription. Delayed data is labelled delayed, but always confirm in your broker.

## Troubleshooting

| Symptom | Likely cause / fix |
|---|---|
| "Failed: timeout" | Wrong endpoint (for example OpenD's port 11111) or bridge not running. Use `http://127.0.0.1:8888`. |
| "network error or CORS blocked" | Bridge not running, wrong port, or an old bridge without CORS support. Use the supplied `bridge.py`; allow local-network access in Chrome/Edge. |
| Bridge log shows `OPTIONS ... 404` | The bridge doesn't handle the browser's pre-check. Use the supplied `bridge.py`. |
| "authentication error" | Wrong or expired API key (Polygon) or OpenD not logged in. |
| "rate limit reached" | Slow down: use a longer refresh interval or fewer symbols. The app retries with backoff. |
| "OPTIONS DATA UNAVAILABLE" | Provider returned no chain; your plan or permissions may not include options. |
| Port 8888 "forbidden by its access permissions" | Another program or Windows reserves it. Change `BRIDGE_PORT`. |
| No picks | Often correct: nothing met your rules, or the market is closed. Review the *Rejected* list on AUTO-PICKS. |
| Paper trades disappeared | Browser data was cleared, or you opened the page from a different address. Export the journal regularly. |
